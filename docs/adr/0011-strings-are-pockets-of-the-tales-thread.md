# Strings are pockets of the tale's thread

Seth decided this on 2026-10-28. The words are GLOSSARY.md's.

## Why

Strings lived in a table of their own, with their own screen. Nothing updated them as the tale
moved, and on the Workbench an open string could only be tied off or let go: there was no way to
keep one as part of the tale. The tale's thread (ADR 0010) already holds what is true of the whole
tale and moves with it at each hem.

## The decision

- **A string is a pocket of the tale's thread**, of kind *promise* (set up to pay off) or *open
  question* (kept open, never answered by the model).
- **On** means in play and sent to the model (what "summoned" meant); **off** means set aside.
- **Each hem chalks where each in-play string stands now**, beside where the tale stands; sewn in,
  the old version is kept with a diff. The first version is the string as it was set up.
- **A chalked string is accepted with Sew it in**, which adds it as a pocket of the tale's thread,
  switched on.
- **Tied off and Let go** switch the pocket off and mark it; history keeps it; switching it on again
  reopens it.
- **The strings table goes.** Existing strings move to the tale's thread once, after a backup. The
  Strings screen becomes a filtered view of these pockets.
